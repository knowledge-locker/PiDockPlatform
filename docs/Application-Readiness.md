## What can run now

The disposable [shared app sample](../tools/PiDock.AppUi.Sample/README.md) runs in Development, inside the real PiDockOS shell with the versioned shared styles. Its server-side latch and monotonic three-second delayed indicator continue independently of browser subscriptions. The authenticated bridge carries Start/Stop/enable/reset commands and live normal/effective watch values. This is a fixture, not a Logic Engine runtime, graph editor or physical controller.

The connected launcher now exercises the actual shared HTTPS I/O and engineering endpoints. Start/Stop stimuli use leased simulated inputs; typed runtime frames drive the latch/timer; queued bank-enable writes are acknowledged; normal/effective output values feed one three-pin simulated output batch. Named bridge commands perform force, release and release-all with displayed runtime/revision fencing. The browser shows the last accepted GPIO batch separately from the engineering acknowledgement.

The fixture provisions isolated scoped credentials and pins its temporary service certificate without changing machine trust. A private Unix-only review process adapter now supervises sample lifecycle and serves the same access protocol as the actual Docker broker. Shared startup-bound authority revokes leases and fences engineering on observed lifecycle loss; this does **not** prove Docker isolation, physical fallback or atomic cross-process timing. The low-rate control cycle is 1.5 seconds; independent display updates run twice per second. Shutdown releases forces/leases where reachable. A fault holds unavailable until an explicit reset creates a new instance.

Docker Desktop lifecycle, connected health/automatic recovery, integrated install/update/restore/remove and actual broker/appliance executable restart validation now pass in the disposable tool described below. Remaining release conformance includes Pi/systemd and disruptive target interruption validation; Logic Engine must implement and validate its own program/producer correctness. The shared startup-bound authority and process/Docker fixture connections are implemented. Physical drivers and board-specific electrical/fault acceptance remain separate.

The current app service limit is 120 requests/minute per credential. Plan a low-rate fixture within that bound. A 20 ms PLC scan and high-rate physical I/O require a separately validated adapter/transport; increasing a browser refresh rate does not supply one.
